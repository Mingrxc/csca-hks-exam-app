# CSCA & HKS 留学生考试刷题小程序 — 整体项目 Prompt

---

## 一、项目概述

### 1.1 产品定位
面向准备 CSCA（Chinese Social and Cultural Adaptation）与 HKS（汉语水平考试）的留学生群体，提供一套「以刷题为核心、错题复盘为引擎、社交共学为辅助」的微信小程序，帮助用户高效备战考试，从"刷题—纠错—举一反三—巩固掌握"形成完整学习闭环。

### 1.2 目标用户
- 在华的留学生（本科、预科、语言生）
- 备考 CSCA 或 HKS 的海外申请者
- 需要碎片化刷题、系统化错题管理的考生

### 1.3 核心价值主张
> **以题带学，用错题驱动进步。** 不做大而全的网课平台，专注"刷"和"纠"，让每一道错过的题都不再错第二次。

## 二、功能模块规划

### 第一优先级：核心刷题闭环（MVP 必须）

#### 2.1 题库与组卷引擎

| 子功能 | 说明 |
|--------|------|
| 题库管理 | 按考试类型（CSCA / HKS）、科目、知识点、难度、题型（单选/多选/判断/填空）分类存储题目 |
| 智能组卷 | 支持「随机组卷」「知识点专项」「难度递进」「模拟真题比例」四种组卷策略 |
| 试卷发布 | 每套模拟卷有唯一 ID，可分享给好友 |
| 题目呈现 | 支持题干文本、图片、音频（听力题）|

**组卷策略细节：**
- 随机组卷：用户选择题目总数，系统按设定比例从各知识点随机抽取
- 知识点专项：用户选择 1-N 个知识点标签，系统聚合该领域的题目
- 难度递进：前 30% 简单 → 40% 中等 → 30% 困难，模拟真实考试梯度
- 模拟真题：按照历年真题的知识点分布比例来组卷（需预先配置比例模板）

#### 2.2 答题与批改

| 子功能 | 说明 |
|--------|------|
| 考试模式 | 全屏沉浸，倒计时，不可退出，提交后统一批改 |
| 练习模式 | 逐题作答，即时反馈对错与解析，无时间限制 |
| 自动批改 | 客观题自动判分；主观题（填空）支持模糊匹配与关键词匹配 |
| 答题卡 | 实时显示已答/未答/标记状态，支持跳题 |
| 成绩报告 | 分数、正确率、用时、各知识点正确率雷达图 |

#### 2.3 错题本（核心差异化功能）

| 子功能 | 说明 |
|--------|------|
| 自动收录 | 答错的题自动进入错题本，记录错误次数、错误时间、错误选项 |
| 错题分类 | 按考试类型、科目、知识点、错误次数多级分类 |
| 错题重做 | 从错题本中选题重新作答，支持「只做错 2 次以上的」「只做本周错题」等筛选 |
| 掌握标记 | 连续答对 N 次（可配置，默认 3 次）自动移入「已掌握」；也可手动标记 |
| 错题导出 | 支持导出为 PDF / 图片，方便打印复习 |
| 错题统计 | 错误趋势图、薄弱知识点排行、错误类型分布 |

#### 2.4 错题分析与举一反三

| 子功能 | 说明 |
|--------|------|
| 逐题解析 | 每道题展示：正确答案 + 解析 + 知识点标签 + 易混选项辨析 |
| 错因分析 | 用户可标记错因（"知识点不会""粗心""审题错误""时间不够"等），系统按错因聚类 |
| 举一反三 | 错题详情页底部推荐 3-5 道「同知识点」「同题型」「同难度」的相似题目 |
| 推荐逻辑 | 基于知识点标签 + 难度 + 历史错题数据的协同过滤 |

## 三、技术架构建议

### 3.1 推荐技术栈

| 层级 | 推荐方案 | 备选方案 |
|------|----------|----------|
| 小程序框架 | **uni-app (Vue3)** | 原生微信小程序、Taro (React) |
| UI 组件库 | **uView Plus / uni-ui** | Vant Weapp、自定义 |
| 后端框架 | **Node.js + Express/Koa** 或 **Python FastAPI** | Spring Boot、Go Gin |
| 数据库 | **MySQL** (用户/题库/试卷) + **Redis** (缓存/排行) | PostgreSQL、MongoDB |
| ORM | **Prisma** (Node.js) / **SQLAlchemy** (Python) | TypeORM、Drizzle |
| 文件存储 | **微信云存储** 或 **阿里云 OSS** | 七牛云、腾讯云 COS |
| 消息推送 | **微信服务通知** (订阅消息) | — |

### 3.2 推荐理由

- **uni-app**：一套代码可编译为微信小程序 + H5 + App，未来扩展性好
- **FastAPI (Python)**：数据处理友好，后期接入 AI 错题讲解时 Python 生态优势大
- **MySQL + Redis**：题库结构规整（关系型），排行榜/打卡缓存用 Redis 天然合适
- **微信云开发**：如果是小团队或个人开发，云开发可省去后端部署运维，直接调用云函数

## 五、关键页面与交互流程

### 5.1 用户核心路径

```
打开小程序
  │
  ├─→ [首页] 今日推荐试卷 / 错题复习提醒 / 打卡入口
  │     │
  │     ├─→ [刷题] 选择组卷策略 → 答题 → 交卷 → 成绩报告
  │     │     └─→ 查看错题 → 举一反三推荐 → 继续刷题
  │     │
  │     ├─→ [错题本] 浏览错题 → 筛选 → 重做 → 掌握标记
  │     │
  │     ├─→ [论坛] (可选) 浏览讨论 / 提问
  │     │
  │     ├─→ [好友] (可选) 好友动态 / 发起 PK
  │     │
  │     └─→ [我的] 学习数据 / 成就勋章 / 设置
```

| 页面 | 核心内容 |
|------|----------|
| 首页 | 考试倒计时、今日刷题进度、错题数提醒、快速开始刷题按钮 |
| 组卷页 | 选择考试类型 → 选择组卷策略 → 确认题目数/难度 → 开始 |

## 六、UI/UX 设计方向

### 6.1 视觉风格
- **色调**：主色使用沉稳的蓝紫色系（学术感），辅色使用暖橙色（激励感）
- **字体**：标题使用系统默认粗体，正文保持良好的可读性
- **布局**：卡片式布局为主，信息密度适中，避免刷题页面的视觉干扰
- **动效**：答题正确时绿色微动，错误时轻微抖动 + 红色闪烁；连续打卡有火焰动效

### 6.2 设计原则
- 刷题页面极简：题干 + 选项，去掉所有无关 UI 元素
- 反馈即时：练习模式点选即判，考试模式交卷即出分
- 降低焦虑：不展示实时正确率，只在交卷后呈现完整报告
- 正向激励：多给鼓励性文案（"又消灭了 3 道错题！""比上周进步了 12%！"）

## 八、非功能性需求

### 8.1 性能
- 答题页加载 < 1 秒（预加载下一题）
- 组卷响应 < 2 秒
- 支持离线答题，联网后同步记录

### 8.2 安全
- 微信登录 + JWT 鉴权
- API 接口防刷（频率限制）
- 题目数据加密存储
- 用户隐私可控（好友可见范围设置）

### 8.3 可维护性
- 题库支持批量导入（Excel/JSON）
- 后台管理面板（题目 CRUD、用户管理、数据看板）
- 接口文档自动化（Swagger / Apifox）

## 九、关键考量与风险

| 风险 | 应对 |
|------|------|
| 题库内容质量 | MVP 阶段可爬取公开题目或与培训机构合作导入；后续引入用户贡献 + 审核机制 |
| 微信小程序审核 | 论坛/UGC 内容需要内容安全资质，MVP 阶段先不做论坛或用微信内容安全 API |
| 用户留存 | 错题本 + 打卡 + 推送形成习惯回路，降低用户流失 |
| 竞品分析 | 现有刷题小程序多为通用型，专注"留学生+特定考试"的垂类定位是优势 |
