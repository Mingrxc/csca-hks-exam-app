## 用户体验

- 首次打开、主动退出及登录过期后为游客，已有有效登录态会恢复。启动、切换导航及普通请求不会自动调用微信登录。
- 游客可浏览首页、刷题、我的、语言设置、关于及公告。点击练习、错题、收藏、学习记录或反馈等功能时提示“登录后即可使用”，提供“去登录”和取消。登录后继续之前选择的功能。
- 游客“我的”显示默认头像、未登录、点击登录，不显示编号和退出入口。登录后显示头像、昵称及可复制的lw编号，并提供退出登录。
- 用户主动使用微信头像选择和昵称输入组件，可稍后补充资料。头像经服务器校验、缩放和重编码后持久保存，资料修改同步到共享用户状态与首页；不承诺静默读取或持续同步微信资料。
- 退出及账号切换清空正在展示的私人数据；未完成练习、考试偏好和反馈草稿按账号隔离，服务器历史保留。旧版无归属的 `exam_active_progress_v2` 不自动认领，已提交记录仍从服务器读取。

## 数据库与身份

保留 `users.id` 整数主键、OpenID唯一身份和既有外键。新增唯一非空 `users.user_code`，历史用户按原id回填（id=1对应lw001），新用户由事务计数表 `user_code_counters` 分配。从lw001开始、至少三位，超过999自然扩展，已发编号不会因删除用户而复用。重复登录仍为同一用户。

`lw000` 仅预留给经核实的本人账号，本次没有绑定或据此授予管理权限。公开资料接口不能修改编号或OpenID。受保护接口必须提供JWT，开发环境也不能匿名访问或自动创建测试用户。生产环境禁用微信登录失败后的开发身份回退。

本次不新增管理员页面、角色或授权功能，现有内容维护白名单不扩大。

## 部署配合

先按现有流程备份，更新后端后在服务器现有Python环境、`server`目录运行：

```text
python -m alembic current
python -m alembic upgrade head
python -m alembic current
```

最新迁移0011依赖0010，服务器若仍在0009，会顺序执行0010、0011。不清库、不重导题，不运行reset_database。建议先完成后端升级和重启，再上传1.5.4小程序。仅上传前端不能增加用户字段或生成公告。

头像目录由 `USER_AVATAR_ROOT` 配置，默认在仓库同级的 `user_uploads/avatars`（生产例如 `/opt/laowai/user_uploads/avatars`）。允许服务进程读写，纳入用户数据备份，发布替换代码时保留。前端通过原API域名上传和读取，微信后台的uploadFile合法域名需包含该HTTPS API域名。上传限制2MB、PNG/JPEG/WebP，保存为最大512像素JPEG。Pillow原本就是ReportLab依赖，本次仅补充直接声明，没有安装依赖。

本人账号核实后，从项目根目录使用服务器既有环境先预览，再明确绑定：

```text
python scripts/assign_owner_code.py --user-id <已核实的内部用户ID>
python scripts/assign_owner_code.py --user-id <已核实的内部用户ID> --apply
```

脚本默认只读；`--apply`仅设置编号，不授予管理员权限。lw000已属另一用户时拒绝覆盖。本人原普通编号退役、不再发放。不要按昵称或普通微信号猜测身份。

公开编号为永久标识，0011不提供删除字段的downgrade；应用回退保留兼容结构、编号及头像文件，不清库回退。
