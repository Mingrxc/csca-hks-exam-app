## 功能与权限

| 身份 | 入口与权限 |
|---|---|
| 游客、普通用户 | “我的”隐藏管理中心；直接访问管理接口也被拒绝 |
| 只读管理员 | 查看总览、用户学习统计、反馈全文和处理状态、公告与内容（含草稿） |
| 唯一主管理员 | 上述全部功能，另可增删只读管理员、发布/编辑/撤下/删除内容、修改反馈状态 |

首版页面为数据概览、用户列表、反馈查看、管理员管理及复用的公告/内容页面。按编号或昵称查找用户，列表及反馈支持分页；学习指标只读，没有用户删除、改分或题库编辑功能。

总览显示用户总数、今日新增、今日答题人数、累计答题、累计试卷、反馈总数和未读反馈。今日以北京时间自然日计算，答题人数按实际作答用户去重，不称为打开小程序的日活。列表展示最近作答时间，不伪造最近登录时间。管理列表不返回OpenID、UnionID、JWT、微信密钥或数据库配置。

反馈全文经用户确认向只读管理员开放。查看反馈不自动改变“未读”状态，标为已读/已处理等操作仅主管理员可做。用户反馈页同步说明“反馈仅开发者及授权管理员可见”。

界面沿用现有配色和中英设置，用户昵称、反馈和公告正文保留原文。管理私有数据不持久化到本地；退出、换号、角色变化立即清除内存内容，旧会话响应和过期并发刷新结果丢弃。

## 首次试用流程

1. 按现有流程备份后，在服务器部署新后端代码并使用既有环境执行 `python -m alembic upgrade head`，达到 `0013_trial_admin_owner`（顺序执行0012、0013），再重启服务。
2. 本次用户已明确指定开发测试账号lw005为临时主管理员。保留lw005、lw000继续预留给正式本人；从服务器项目根目录先预览：

```text
python scripts/bootstrap_admin_owner.py --user-code lw005 --temporary
```

3. 核对预览的内部id、昵称和编号对应lw005测试账号，再明确绑定：

```text
python scripts/bootstrap_admin_owner.py --user-code lw005 --temporary --expected-user-id 预览确认的内部ID --apply
```

默认只读，缺少已核实的内部ID不能写入。--temporary会在同一事务中指定唯一试用主管理员、保留lw005并标记is_temporary=true；不占lw000，不改主键、学习记录或计数器。未加--temporary的正式绑定模式才会将本人编号设为lw000、原普通编号退役。已有主管理员一律不能覆盖，也不能隐式转换临时/正式模式。临时指试用用途，不设自动到期；后续正式账号切换需要单独核实和明确授权，不通过小程序转交。原代码开发阶段只准备工具；本次服务器部署会话另行取得明确确认，已使用核实的内部ID=5完成临时绑定。

4. 使用新小程序构建 `client/dist/build/mp-weixin`，重新进入“我的”刷新资料，主管理员会看到“管理中心”。发布小程序和实际服务器操作需要另行安排。
5. 在“管理员管理”输入对方现有lw编号，查找后核对昵称，确认设为只读管理员。对方先登录建档即可，无需申请、授权码或同意；重新打开/刷新“我的”可看到入口。撤销后下一次接口请求立即拒绝，不依赖JWT重新签发。

0013_trial_admin_owner在0012后追加is_temporary标记，已有记录默认为false，不自动授予或切换任何角色。0012迁移增加 `admin_owner`（仅允许id=1）、`admin_members`、`admin_audit_logs` 三张表，不清库、不重导题、不自动授权任何账号。`lw000`只是展示编号，角色在数据库按内部用户ID关联，编号本身不授予权限。旧 `CONTENT_ADMIN_OPENIDS` 仅兼容配置读取，不再授予任何HTTP管理权限，也不会自动转为主管理员。

主管理员不能从小程序被撤销或转交，新增管理员固定只读。管理接口每次从数据库校验权限，写入与操作者/时间/目标审计记录同一事务提交。旧的assign_owner_code.py仅改编号，不能替代主管理员绑定工具。服务器维护工具属于受信任的运维访问，不作为小程序管理员入口。
